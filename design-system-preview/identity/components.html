Demain components

The parts every screen of the app is built from, drawn with the identity tokens. Each control keeps the behaviour the app already has (labels, linked errors, native dialog, toasts that name their kind); only shape and colour are new. Amounts are synthetic.

Typeface

Host Grotesk, SIL Open Font License 1.1, no reserved font name: it can ship inside the app and its Docker image. Chosen by the owner among ten open neo-grotesks measured against Neue Montreal, the face named in 13:54: the same proportions of capitals to lowercase and the same stem, a little wider and more open.

Rules

Regular for text and amounts, Medium for labels, headings and buttons, Bold only where a single figure must dominate. No other family.

The wordmark is set in the same face, Host Grotesk Medium, converted to outlines.

Buttons and their states

Ink primary, one per screen (06:44, 08:16, 12:21); neutral secondary next to it (12:21); text link for a third action (13:19). Destructive red only on the confirm button inside a dialog. Hover and pressed take one tone step, faded over --motion-duration-state; the button never changes size or position, and with reduced motion the step is instant. Disabled uses explicit colours instead of transparency, so its contrast is measured. Pending keeps the fill, changes the label and sets aria-busy.

Adding a transaction

The add-transaction form of the app becomes three steps, retained by the owner on 11 Nov 2026 from the proposals of form-proposals.html. Step 1 takes the type and the amount, typed or tapped on the keypad, under the exact-syntax rule. Step 2 is the label, with suggestions from history, and the category, "Later" sending it to the to-categorize queue. Step 3 recaps and edits in place, picks the date with the date picker, asks for the receiving account of a transfer, and keeps the note and the payment mode under "More details". Every choice is a chip or a segment with an icon, a colour and a word. The colour pairs of the flow are measured on form-proposals.html. On a computer, from 760 px of available width, the same flow fits one screen in two columns: the amount, the label and the category on the left, the date, the account and the save button on the right. It is typed on the keyboard, so the keypad, the steps and the recap go; the save button checks the amount and the label. Use the switch to see both layouts. A transfer that does not fit under the ceiling of the receiving account opens a step of its own before saving: what fits, what does not, and where the surplus goes (try Move, 200 to Savings A; 50.00 is left under each synthetic ceiling).

Custom pickers

Selects and dates use custom pickers instead of the browser's, built on the WAI-ARIA select-only combobox and date picker dialog patterns: full keyboard support, the selected option carries a check, today keeps its blue ring and the chosen day is ink, with no hover. In the app they need JavaScript, so the server should render the native control first and swap it on load.

Field states

Hover darkens the border to ink. Focus adds the blue ring, the only place besides today where blue appears. Invalid doubles the border in red and writes "Error:" before the message, so colour is never alone. Disabled fades to the inner surface. Read-only drops the fill but keeps the 3:1 border and ink text: unlike a disabled field, it can still be focused, selected and read.

Fields with an exact syntax

When a field expects an exact syntax, the browser refuses any other character as it is typed, pasted or dropped, and says why in a polite live message instead of failing silently. An incomplete value is flagged when the field is left. The server checks the same rule again and stays the authority, since the browser can always be bypassed. An amount takes digits and one comma or point, with the decimals of its currency; spaces in a pasted amount are removed. A currency code takes three letters and is uppercased. A balance that can be negative (an opening balance, a balance check, an imported row) keeps the same amount syntax, without a sign: a Credit or Debit choice next to it gives the side, so the sign never has to be typed.

Feedback

A toast names its kind in words ("Success.", "Error."), the tinted disc only repeats it. A success leaves after 8 seconds unless pointed at or focused; an error stays. The confirmation dialog is the native one: Cancel takes the focus first, Escape closes it (as ConfirmActionButton). Layers fade in and rise (--motion-duration-enter, --motion-offset) and leave faster (--motion-duration-exit); the button below shows a toast arriving and leaving. With reduced motion, everything is instant.

English and French

Amounts and dates come from Intl, as formatAmount and formatCalendarDate do in the app: the values below are computed by this page from integer minor units, not typed. French groups thousands with a narrow no-break space (U+202F) and puts the euro after a no-break space. The upstream Host Grotesk file has no U+202F glyph, so the shipped file maps it to the face's own thin space (0.15 em): the width no longer depends on the device, and the Intl output stays as it is. Labels are written in sentence case and uppercased by CSS, so accented capitals stay correct.
